Appendix 04 • Microservice Blueprint

Production Axum 0.8 Microservice Architecture

From Express & Mongoose to Axum, Tower Middleware, Sub-State Extractors, SQLx Pooling, and Graceful SIGTERM/SIGINT Shutdown.

Key takeaways

  • Axum 0.8 route paths use /{id} for parameters and /{*rest} for wildcards; the 0.7 syntax /:id panics when the route is registered.
  • An Axum 0.8 server binds a tokio::net::TcpListener and runs axum::serve(listener, app); .with_graceful_shutdown(signal) stops accepting connections and waits for in-flight requests.
  • Axum shares dependencies through the State<T> extractor and Router::with_state; implementing FromRef lets a handler extract only one field of the app state, such as the database pool.
  • In an Axum handler, extractors that read only request metadata (Path, Query, State, HeaderMap) can appear in any order, but at most one body extractor (Json, String, Bytes) is allowed and it must be the last argument.
  • SQLx's Pool::close().await rejects new acquires, closes idle connections and waits until checked-out connections are released and closed, so calling it after the HTTP server stops gives PostgreSQL a clean disconnect.

1. Entrypoint & Graceful Shutdown with Pool Draining

Axum 0.7 removed axum::Server in favour of a tokio::net::TcpListener passed to axum::serve(), and 0.8 keeps that API. Axum 0.8 changed path syntax: parameters are written /{id} and wildcards /{*rest}. Graceful shutdown listens for both SIGINT (Ctrl+C) and Unix SIGTERM, which Kubernetes sends before a pod is killed (followed by SIGKILL once terminationGracePeriodSeconds, 30 seconds by default, runs out). Once the HTTP server has finished in-flight requests, the application awaits db.close().await so PostgreSQL connections are closed cleanly before the process exits.

// src/main.rs
use axum::{routing::{get, post}, Router};
use tokio::net::TcpListener;
use tower_http::trace::TraceLayer;

mod error;
mod routes;
mod state;

use state::AppState;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 1. Initialize structured logging
    tracing_subscriber::fmt::init();

    // 2. Build shared application state (cheap to clone: the pool is an Arc inside)
    let state = AppState::new().await?;

    // 3. Assemble routes with State and Tower middleware (Axum 0.8 path syntax)
    let app = Router::new()
        .route("/healthz", get(routes::health::check))
        .route("/api/users", post(routes::users::create_user).get(routes::users::list_users))
        .route("/api/users/{id}", get(routes::users::get_user))
        .layer(TraceLayer::new_for_http())
        .with_state(state.clone());

    // 4. Bind a Tokio TCP listener
    let addr = "0.0.0.0:3000";
    let listener = TcpListener::bind(addr).await?;
    tracing::info!("Listening on {}", addr);

    // 5. Serve until SIGINT / SIGTERM, then wait for in-flight requests
    axum::serve(listener, app)
        .with_graceful_shutdown(shutdown_signal())
        .await?;

    // 6. Close the pool: closes idle connections, waits for checked-out ones to be released
    tracing::info!("Draining PostgreSQL connection pool...");
    state.db.close().await;
    tracing::info!("PostgreSQL pool closed. Server shutdown complete.");

    Ok(())
}

async fn shutdown_signal() {
    let ctrl_c = async {
        tokio::signal::ctrl_c()
            .await
            .expect("failed to install Ctrl+C handler");
    };

    #[cfg(unix)]
    let terminate = async {
        let mut sig = tokio::signal::unix::signal(tokio::signal::unix::SignalKind::terminate())
            .expect("failed to install SIGTERM handler");
        sig.recv().await;
    };

    #[cfg(not(unix))]
    let terminate = std::future::pending::<()>();

    tokio::select! {
        _ = ctrl_c => tracing::info!("Received SIGINT (Ctrl+C), draining HTTP connections..."),
        _ = terminate => tracing::info!("Received SIGTERM, draining HTTP connections..."),
    }
}

2. Dependency Injection: State, FromRef & Extractor Ordering Rules

Unlike Express's untyped req.app.locals, Axum injects dependencies through typed extractors. Implement FromRef (or #[derive(FromRef)] with the macros feature) so handlers can extract only the sub-state they need.

Extractor Ordering Rule:

Extractors implementing FromRequestParts (e.g. Path, Query, State, HeaderMap) read only request metadata and may appear in any order.
An extractor implementing only FromRequest consumes the request body (e.g. Json, String, Bytes), so a handler can have at most one and it must be the last argument. Breaking this rule produces a compile error saying the handler function does not implement Handler<_, _>; add #[axum::debug_handler] to the function to get a message that names the offending argument. 

// src/state.rs
use axum::extract::FromRef;
use sqlx::{Pool, Postgres, postgres::PgPoolOptions};

#[derive(Clone)]
pub struct AppState {
    pub db: Pool<Postgres>,
}

impl AppState {
    pub async fn new() -> Result<Self, sqlx::Error> {
        let db_url = std::env::var("DATABASE_URL").expect("DATABASE_URL must be set");
        let db = PgPoolOptions::new()
            .max_connections(20)
            .connect(&db_url)
            .await?;
        Ok(Self { db })
    }
}

// Enables handlers to extract State(db): State<Pool<Postgres>> directly
impl FromRef<AppState> for Pool<Postgres> {
    fn from_ref(app_state: &AppState) -> Self {
        app_state.db.clone()
    }
}
// src/error.rs
use axum::{http::StatusCode, response::{IntoResponse, Response}};

pub enum AppError {
    NotFound(String),
    Database(sqlx::Error),
}

// Lets handlers use `?` on SQLx calls
impl From<sqlx::Error> for AppError {
    fn from(err: sqlx::Error) -> Self {
        AppError::Database(err)
    }
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        match self {
            AppError::NotFound(msg) => (StatusCode::NOT_FOUND, msg).into_response(),
            AppError::Database(err) => {
                tracing::error!(error = %err, "database error");
                (StatusCode::INTERNAL_SERVER_ERROR, "internal server error").into_response()
            }
        }
    }
}

// src/routes/health.rs
pub async fn check() -> &'static str {
    "ok"
}
// src/routes/users.rs
use axum::{
    extract::{Path, Query, State},
    http::StatusCode,
    Json,
};
use serde::{Deserialize, Serialize};
use sqlx::{Pool, Postgres};
use uuid::Uuid;
use crate::error::AppError;

#[derive(Deserialize)]
pub struct CreateUserPayload {
    pub email: String,
}

#[derive(Deserialize)]
pub struct PaginationQuery {
    #[serde(default = "default_page")]
    pub page: u32,
    #[serde(default = "default_limit")]
    pub limit: u32,
}

fn default_page() -> u32 { 1 }
fn default_limit() -> u32 { 20 }

#[derive(Serialize, sqlx::FromRow)]
pub struct UserResponse {
    pub id: Uuid,
    pub email: String,
}

// POST /api/users
// ORDER RULE: State (request parts) first. Json (body consumer) is LAST.
pub async fn create_user(
    State(db): State<Pool<Postgres>>,
    Json(payload): Json<CreateUserPayload>, // Consumes the request body
) -> Result<(StatusCode, Json<UserResponse>), AppError> {
    let user = sqlx::query_as::<_, UserResponse>(
        "INSERT INTO users (id, email) VALUES ($1, $2) RETURNING id, email"
    )
    .bind(Uuid::new_v4())
    .bind(&payload.email)
    .fetch_one(&db)
    .await?;

    Ok((StatusCode::CREATED, Json(user)))
}

// GET /api/users?page=1&limit=20
// Query and State both implement FromRequestParts, so their order is free
pub async fn list_users(
    Query(pagination): Query<PaginationQuery>,
    State(db): State<Pool<Postgres>>,
) -> Result<Json<Vec<UserResponse>>, AppError> {
    let limit = pagination.limit.clamp(1, 100) as i64; // cap client-supplied page size
    let offset = (pagination.page.max(1) as i64 - 1) * limit;
    let users = sqlx::query_as::<_, UserResponse>(
        "SELECT id, email FROM users ORDER BY email LIMIT $1 OFFSET $2"
    )
    .bind(limit)
    .bind(offset)
    .fetch_all(&db)
    .await?;

    Ok(Json(users))
}

// GET /api/users/{id}
pub async fn get_user(
    Path(id): Path<Uuid>,
    State(db): State<Pool<Postgres>>,
) -> Result<Json<UserResponse>, AppError> {
    let user = sqlx::query_as::<_, UserResponse>(
        "SELECT id, email FROM users WHERE id = $1"
    )
    .bind(id)
    .fetch_optional(&db)
    .await?
    .ok_or_else(|| AppError::NotFound("User not found".into()))?;

    Ok(Json(user))
}

Frequently asked questions

How do I write a route parameter like Express's /users/:id in Axum?
In Axum 0.8, write .route("/users/{id}", get(handler)) and read the value with Path(id): Path<Uuid> or another deserializable type. Catch-all segments use /{*rest}. The Express-style /:id syntax was used up to Axum 0.7 and panics at route registration in 0.8.
What replaced app.listen() and axum::Server in Axum?
Bind a tokio::net::TcpListener and pass it with the router to axum::serve(listener, app).await. This API arrived in Axum 0.7 and is unchanged in 0.8. Chain .with_graceful_shutdown(future) to stop on a signal and let in-flight requests finish.
How do I share a database pool between Axum handlers?
Put the pool in a Clone state struct, attach it with Router::with_state(state), and extract it with State<AppState>. Implement FromRef<AppState> for the pool type if a handler should receive only the pool. SQLx's Pool is reference-counted internally, so cloning it is cheap.
Why does my Axum handler fail with "the trait Handler is not implemented"?
The most common cause is a body extractor such as Json that is not the last argument, or two body extractors in one handler. Other causes are an argument type that is not an extractor or a return type that does not implement IntoResponse. Adding #[axum::debug_handler] to the function makes the compiler point at the exact argument.
Do I still need #[async_trait] for custom Axum extractors?
No. Since Axum 0.8, FromRequestParts and FromRequest use native async functions in traits, so implementations are written without the #[async_trait] macro. Code migrated from 0.7 should remove the attribute.
