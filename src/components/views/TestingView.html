Appendix 06 • Quality & Testing

Testing & Mocking: Jest / Vitest vs Rust

Unit tests, external integration tests, serial database testing, and trait mocking with mockall.

1. Built-in Synchronous & Async Unit Tests

Unit tests live right inside your source files in a #[cfg(test)] module. They can access private functions and run concurrently by default.

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_sync_math() {
        assert_eq!(2 + 2, 4);
    }

    #[tokio::test]
    async fn test_async_fetch() {
        let result = async_query_user(1).await;
        assert!(result.is_ok());
    }
}

2. External Integration Tests & Directory Convention

In Node.js, test runners search for *.test.ts anywhere. In Rust, Cargo compiles each file directly under tests/ as an independent external crate. To share fixtures without Cargo treating them as standalone tests, use the tests/common/mod.rs convention:

my_project/
├── Cargo.toml
├── src/
│   ├── lib.rs
│   └── main.rs
└── tests/
    ├── common/
    │   └── mod.rs          # Shared fixture module (NOT compiled as a test binary)
    └── integration_test.rs # Root test crate (tests only public APIs)

Shared helper in tests/common/mod.rs:

// tests/common/mod.rs
pub fn setup_test_db() -> String {
    // Spin up test db or create temporary schema
    "postgres://localhost:5432/test_db".to_string()
}

Integration test in tests/integration_test.rs:

// tests/integration_test.rs
use my_project::app; // Imported as an external crate
mod common;

#[tokio::test]
async fn test_create_user_flow() {
    let db_url = common::setup_test_db();
    let response = app::run_migration(&db_url).await;
    assert!(response.is_ok());
}

3. Isolated Database Tests: --test-threads=1

Rust's built-in test harness runs all tests across multiple threads simultaneously. When testing stateful database transactions or truncating tables, concurrent tests will clash and cause flaky failures.

To run tests serially in a single thread:

# Pass --test-threads to the test binary via Cargo
cargo test -- --test-threads=1

# Or run only integration tests serially:
cargo test --test integration_test -- --test-threads=1

# Alternatively, set the environment variable:
RUST_TEST_THREADS=1 cargo test
Node.js Comparison: In Jest, this is the equivalent of running with jest --runInBand. In Rust, you can also use crates like serial_test (#[serial] attribute) to only force DB tests into serial execution while keeping pure unit tests parallel.

4. Mocking Traits with mockall

JavaScript allows runtime monkey-patching (jest.mock('./api')). In Rust, dependencies are abstracted behind traits and mocked at compile time using mockall:

#[mockall::automock]
pub trait UserRepository {
    fn get_user(&self, id: u32) -> Result<String, &'static str>;
}

#[test]
fn test_service_with_mock() {
    let mut mock = MockUserRepository::new();
    mock.expect_get_user()
        .with(mockall::predicate::eq(42))
        .returning(|_| Ok("Alice".to_string()));

    assert_eq!(mock.get_user(42).unwrap(), "Alice");
}
