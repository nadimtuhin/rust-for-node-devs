Rosetta Stone Syntax Cheatsheet

Side-by-side TypeScript and Rust idioms, from variables to shared state across threads.

Key takeaways

  • Rust bindings are immutable by default; let mut is the opt-in, and Rust's let is closer to TypeScript's const than to its let.
  • TypeScript's number is a 64-bit float, while Rust makes you pick an exact integer or float type such as i32, u64 or f64.
  • The ? operator returns early with the error, converting it with From, which replaces most try/catch-and-rethrow code.
  • tokio::try_join! is the closest match to Promise.all: it waits for all futures and returns the first error.
  • A Rust HashMap does not preserve insertion order the way a JavaScript Map does.

Frequently asked questions

What is the difference between String and &str in Rust?
String is an owned, growable UTF-8 buffer on the heap, and &str is a borrowed view into UTF-8 text owned by something else. Functions usually take &str as a parameter so they accept both, and return String when they build new text. String literals like "hello" have type &'static str.
What replaces null and undefined in Rust?
Option<T>, which is either Some(value) or None. The compiler will not let you use the inner value until you handle the None case, for example with match, if let, unwrap_or or the ? operator. Safe Rust has no null references.
Is there a try/catch in Rust?
No. Recoverable errors are values of type Result<T, E>, and the ? operator returns the error to the caller early. Panics exist for bugs and unrecoverable states, and they are not meant for normal error handling.
What is the Rust equivalent of Promise.all?
tokio::try_join! is the closest match: it runs futures concurrently and returns the first error, like Promise.all rejecting. tokio::join! waits for every future and returns all results, closer to Promise.allSettled. For a dynamic number of tasks, use tokio::task::JoinSet.
Are Rust traits the same as TypeScript interfaces?
They are similar contracts but work differently. TypeScript interfaces are structural, so any object with the right shape fits, and they are erased at runtime. Rust traits are nominal, so a type must have an explicit impl block, and traits can also provide default methods and be implemented for types you did not write.
