LeetCode in Rust (JS vs Rust)

Seven classic LeetCode problems solved in Rust, each compared with the JavaScript solution you already know.

Key takeaways

  • LeetCode linked lists in Rust use Option<Box<ListNode>>, where None plays the role of JavaScript's null next pointer.
  • Option::take() moves a value out and leaves None behind, which is how you rewire linked list nodes without fighting the borrow checker.
  • A Rust String is UTF-8 and cannot be indexed with s[i]; for ASCII-only problems, iterate over s.bytes() or index s.as_bytes().
  • HashMap::with_capacity(n) allocates once up front, so inserting n elements never triggers a resize.
  • A Vec works as a stack: push() adds to the end and pop() returns an Option, so popping an empty stack is None instead of undefined.

Frequently asked questions

Can I solve LeetCode problems in Rust?
Yes. Rust is one of the languages LeetCode accepts, and it provides Rust function signatures for most problems. The signatures often take owned types such as Vec<i32> and String, and linked list problems give you a ListNode struct with an Option<Box<ListNode>> next field.
Why are linked lists so hard in Rust?
Each Box node has exactly one owner, so you cannot keep two mutable pointers into the same list the way you would in JavaScript. The usual fix is Option::take(), which moves the next node out and leaves None, so ownership passes along one node at a time. Doubly linked lists need Rc and RefCell or unsafe code.
What is the Rust equivalent of a JavaScript Map or object for LeetCode?
Use std::collections::HashMap for key lookups and HashSet for membership checks. Unlike a JavaScript Map, a Rust HashMap does not keep insertion order; use BTreeMap if you need keys in sorted order. The entry() API lets you insert or update a key in one lookup, which is handy for frequency counts.
How do I index characters of a string in Rust?
You cannot write s[i] on a Rust String, because it is UTF-8 and one character can take several bytes. For ASCII-only inputs, which covers most LeetCode problems, use s.as_bytes()[i] or iterate with s.bytes(). For full Unicode, iterate with s.chars() or collect into a Vec<char>.
How do I use a stack in Rust like a JavaScript array?
Use a Vec: push() adds to the end and pop() removes from the end. pop() returns an Option, so an empty stack gives None, which you handle with match or if let instead of checking for undefined. For a queue, use std::collections::VecDeque.
