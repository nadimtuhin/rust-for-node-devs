Appendix 07 • Artificial Intelligence

Building AI Agents in Rust

Token streaming with Server-Sent Events (SSE) in Axum 0.8, typed tool definitions with rig-core, and local inference with Hugging Face Candle.

Key takeaways

  • Axum streams LLM tokens to a browser with axum::response::sse::Sse, fed by a bounded tokio::sync::mpsc channel so a slow client applies backpressure to the producer.
  • When an SSE client disconnects, Axum drops the response stream, the channel receiver is dropped, and the producer's next send returns an error it can use to stop generating.
  • rig-core is an LLM client library for Rust; its 0.x releases change the API between minor versions, so pin the exact version and check docs.rs for that version before copying examples.
  • In rig-core 0.44 a tool is a type implementing PortableTool (name, description, JSON Schema, async call), and the multi-turn agent loop that executes tool calls lives in the companion rig-agent crate.
  • Candle is Hugging Face's Rust ML framework: it runs models on CPU without Python, and its optional cuda and metal features add GPU backends.

1. Token Streaming Gateway (Axum 0.8 SSE)

Each open SSE connection in Axum is one Tokio task plus its socket buffers. The Tokio tutorial states that a task needs a single allocation and 64 bytes of memory on top of the size of its future, so the number of concurrent streams is usually limited by file descriptors, buffer memory and the upstream model API's rate limits rather than by the runtime. Node.js can also hold many idle SSE connections; the difference is that Tokio's multi-threaded scheduler spreads token parsing and fan-out across all CPU cores without worker_threads.

use axum::{
    response::sse::{Event, KeepAlive, Sse},
    routing::post,
    Json, Router,
};
use futures_util::stream::{Stream, StreamExt};
use serde::Deserialize;
use std::{convert::Infallible, time::Duration};
use tokio::sync::mpsc;
use tokio_stream::wrappers::ReceiverStream;

#[derive(Deserialize)]
pub struct ChatRequest {
    pub prompt: String,
}

pub fn router() -> Router {
    Router::new().route("/chat", post(chat_stream_handler))
}

pub async fn chat_stream_handler(
    Json(req): Json<ChatRequest>,
) -> Sse<impl Stream<Item = Result<Event, Infallible>>> {
    // Bounded channel: the producer waits once 16 tokens are queued and unsent
    let (tx, rx) = mpsc::channel::<String>(16);

    // Stand-in for a model call that yields tokens
    tokio::spawn(async move {
        let _prompt = req.prompt;
        let tokens = ["Rust", " provides", " fearless", " concurrency", " for", " AI."];
        for token in tokens {
            tokio::time::sleep(Duration::from_millis(50)).await;
            // send fails once the client disconnects and Axum drops the stream
            if tx.send(token.to_string()).await.is_err() {
                break;
            }
        }
    });

    // Adapt the mpsc receiver into an SSE event stream
    let stream = ReceiverStream::new(rx).map(|token| Ok(Event::default().data(token)));

    Sse::new(stream).keep_alive(
        KeepAlive::new()
            .interval(Duration::from_secs(15))
            .text("keep-alive-ping"),
    )
}

The browser's EventSource API only sends GET requests. For a POST endpoint like this one, read the stream on the client with fetch() and response.body.getReader(), or switch the route to GET with query parameters.

2. Typed Tool Definitions with rig-core

rig-core fills the role the Vercel AI SDK or LangChain.js fill in Node: one interface over many model providers. Tool arguments deserialize into a Rust struct with Serde, so a malformed tool call from the model becomes a typed error instead of an undefined field at runtime. The snippet below targets rig-core 0.44 (library name rig_core) and uses only calls from that version's docs.rs pages. Older tutorials that use impl Tool with definition() and client.agent(...).build() describe earlier 0.x releases.

// Cargo.toml: rig-core = { version = "=0.44.0", features = ["reqwest"] }
use rig_core::{
    completion::CompletionRequest,
    providers::openai::{self, OpenAI},
    tool::{tool_definition, PortableTool},
};
use serde::Deserialize;
use serde_json::json;

#[derive(Deserialize)]
struct SumArgs {
    a: f64,
    b: f64,
}

struct SumTool;

impl PortableTool for SumTool {
    const NAME: &'static str = "calculate_sum";
    type Args = SumArgs;
    type Output = f64;
    type Error = std::convert::Infallible;

    fn description(&self) -> String {
        "Calculates the sum of two numbers".to_string()
    }

    fn parameters(&self) -> serde_json::Value {
        json!({
            "type": "object",
            "properties": { "a": { "type": "number" }, "b": { "type": "number" } },
            "required": ["a", "b"]
        })
    }

    async fn call(&self, args: Self::Args) -> Result<Self::Output, Self::Error> {
        Ok(args.a + args.b)
    }
}

pub async fn ask_with_tool() -> Result<(), Box<dyn std::error::Error>> {
    // Reads OPENAI_API_KEY (and optional OPENAI_BASE_URL)
    let model = OpenAI::from_env()?.completion(openai::GPT_5_2);

    let request = CompletionRequest::new("What is 142.50 plus 391.25?")
        .tool(tool_definition(&SumTool));
    let response = model.call(request).await?;

    for call in response.tool_calls() {
        println!("tool {:?} args {:?}", call.function.name, call.function.arguments);
    }
    println!("{}", response.text());
    Ok(())
}

One request returns the model's tool calls; it does not run them. To execute the tool, append the result and call the model again, or use the rig-agent crate, which runs that loop for you.

3. Local Inference without Python using Hugging Face Candle

Candle loads safetensors and quantized GGUF models inside your Rust process, with no Python runtime or ONNX export step. The CPU backend is pure Rust; the optional cuda and metal Cargo features add GPU backends, which call the vendor GPU libraries through FFI. The snippet targets candle-core and candle-transformers 0.11.

use candle_core::{Device, IndexOp, Tensor};
use candle_transformers::generation::LogitsProcessor;

// Falls back to the CPU only when the cuda/metal features are not compiled in; with the feature on but no GPU, this returns an error
pub fn select_device() -> candle_core::Result<Device> {
    let cuda = Device::cuda_if_available(0)?;
    if cuda.is_cuda() {
        return Ok(cuda);
    }
    Device::metal_if_available(0)
}

pub fn sample_next_token(
    logits: &Tensor,
    logits_processor: &mut LogitsProcessor,
) -> candle_core::Result<u32> {
    // Reduce to the last position's 1D [vocab_size] logits
    let next_token_logits = match logits.dims() {
        [_, seq_len, _] => logits.i((0, seq_len - 1))?, // [batch, seq, vocab]
        [_, _] => logits.i(0)?,                         // [batch, vocab]
        [_] => logits.clone(),                          // [vocab]
        dims => candle_core::bail!("unexpected logits shape: {dims:?}"),
    };

    // LogitsProcessor::new(seed, temperature, top_p) applies temperature and top-p
    logits_processor.sample(&next_token_logits)
}

Frequently asked questions

How do I stream OpenAI-style tokens to the browser from a Rust server?
Return Sse::new(stream) from an Axum handler, where the stream yields Result<Event, Infallible>. A common pattern is to spawn the model call into a Tokio task that writes tokens into a bounded mpsc channel and wrap the receiver with tokio_stream::wrappers::ReceiverStream. Add KeepAlive so proxies do not close idle connections.
What is the Rust equivalent of the Vercel AI SDK or LangChain.js?
rig-core is the closest match: it wraps many providers (OpenAI, Anthropic, Gemini, Ollama and others) behind one completion interface and supports typed tool definitions. Its agent loop is in the separate rig-agent crate. The API is still 0.x and changes between minor versions, so pin the version you build against.
How do I stop generating tokens when the user closes the browser tab?
Check the result of tx.send(...).await in the producer task and break when it returns an error. When the client disconnects, Axum drops the SSE response stream, which drops the channel receiver, so the next send fails. This is the Rust counterpart of listening for the request's close event in Node.js.
Can I run a local LLM in Rust without Python?
Yes. Hugging Face Candle loads safetensors and GGUF weights and runs inference inside a Rust binary, and candle-transformers ships implementations of common model families. GPU support comes from the optional cuda or metal features; without them Candle runs on the CPU.
Why does EventSource not work with my POST streaming endpoint?
The browser EventSource API only issues GET requests and cannot send a request body. For a POST chat endpoint, read the SSE stream with fetch() and response.body.getReader(), then parse the data: lines yourself.
