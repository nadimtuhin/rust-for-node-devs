Appendix 10 • Philosophy

The Core Philosophy of Rust

Memory safety without a garbage collector, zero-cost abstractions, and data-race-free concurrency, with the conditions that make each one true.

Key takeaways

  • Rust has no tracing garbage collector: each value has one owner, and its memory is freed at a point the compiler decides statically, when that owner goes out of scope.
  • In safe Rust, the borrow checker rejects use-after-free, double free, dangling references and data races at compile time; memory leaks and deadlocks are not prevented.
  • Rust iterator chains are lazy and allocate nothing until a method like collect() runs, while each JavaScript map() or filter() call builds a new array.
  • The Send and Sync auto traits let the compiler refuse to move or share non-thread-safe values, such as Rc<T>, across threads.
  • The typestate pattern encodes states like "authenticated" in the type, so calling a method in the wrong state is a compile error instead of a runtime check.
PILLAR 1

Safety: Compile-Time Ownership Over Tracing GC

Node.js relies on V8's generational garbage collector: a parallel Scavenger for the young generation and a Mark-Compact collector for the old generation, with concurrent marking from V8's Orinoco project. Orinoco shortens main-thread pauses but does not remove them, and a tracing collector needs heap headroom above the live data to run efficiently. When an object is actually freed is up to the collector, not your code.

Rust has no tracing GC. Ownership works like an affine type system (a value can be moved at most once), and RAII runs a value's Drop at a known point: when its owner goes out of scope. Freeing still costs time, but you can see where it happens. Borrow rules enforce aliasing XOR mutability: at any moment you hold either any number of shared references &T or exactly one exclusive reference &mut T, never both. In safe Rust this rejects use-after-free, double free, dangling references and iterator invalidation at compile time. It does not prevent leaks: an Rc cycle or std::mem::forget is safe code that never frees memory.

PILLAR 2

Speed: The Zero-Cost Abstraction Principle

Rust adopts Bjarne Stroustrup's zero-overhead principle as a design goal: "What you don't use, you don't pay for. And further: What you do use, you couldn't hand code any better." It is a goal the compiler usually meets for iterators and generics, not a guarantee for every program.

In TypeScript, arr.map(f).filter(g) builds a new intermediate array at each step. In Rust, iter().map(f).filter(g) is lazy: no collection is allocated until collect(), and closures are plain values, not heap objects. Through monomorphization and inlining, LLVM typically compiles such a chain to the same machine code as a hand-written loop, and can auto-vectorize it when bounds checks are proven unnecessary. The Rust Book's "Comparing Performance: Loops vs. Iterators" section shows this with a benchmark.

PILLAR 3

Fearless Concurrency: The Send & Sync Auto Traits

In Node.js, your JavaScript runs on one event loop thread per isolate. Some blocking work (file system, DNS lookup, crypto, zlib) goes to libuv's thread pool, which has 4 threads by default and can be resized with UV_THREADPOOL_SIZE. worker_threads give you more JS threads, but objects are copied between them by structured clone; shared mutable memory is limited to SharedArrayBuffer with manual Atomics synchronization.

Rust lets threads share typed memory, and safe Rust cannot express a data race. Two auto traits do the work; the compiler implements them for a type automatically when all its fields implement them:

  • Send: ownership of the value can be transferred to another thread.
  • Sync: the value can be shared by reference across threads. Formally, T is Sync exactly when &T is Send.

Passing non-thread-safe state such as Rc<RefCell<T>> to std::thread::spawn fails to compile with error E0277, which says the type cannot be sent between threads safely. The thread-safe version is Arc<Mutex<T>>. These guarantees cover data races only: deadlocks and higher-level race conditions (for example, check-then-act bugs) are still possible.

PILLAR 4

Correctness: The Typestate Pattern & Parse, Don't Validate

In JavaScript, invalid states are usually caught by runtime checks (e.g. if (!req.isAuthenticated) throw new Error(...)), and every call site has to remember to make that check.

Rust code often follows "Parse, Don't Validate" (Alexis King, 2019): check input once and return a type that proves the check passed. The typestate pattern applies the same idea to state machines using zero-sized marker types. A Connection<Unauthenticated> is consumed by value by authenticate(), which returns a Connection<Authenticated>. If send_query() exists only on Connection<Authenticated> and the struct's fields are private, calling it on an unauthenticated connection is a compile error. The marker is stored as PhantomData<State>, which takes zero bytes at runtime.

Frequently asked questions

Does Rust have a garbage collector like Node.js?
No. Rust frees each value when its single owner goes out of scope, and the compiler decides where that happens. For shared ownership you opt into reference counting with Rc or Arc, which frees the value when the last reference is dropped.
Is Rust 100% memory safe?
Safe Rust is memory safe: the compiler rejects use-after-free, double free, dangling references and data races. Code inside unsafe blocks can break these rules, and the standard library relies on carefully reviewed unsafe code internally. Memory leaks are considered safe, so an Rc reference cycle can still leak.
What does zero-cost abstraction mean in Rust?
It means a high-level feature should compile to code as fast as what you would write by hand without it. Generics are monomorphized into specialized copies, and iterator chains are usually inlined into a plain loop. The cost moves elsewhere: longer compile times and larger binaries.
What are Send and Sync in Rust?
Send marks a type whose values can be moved to another thread, and Sync marks a type that can be shared between threads by reference. The compiler implements both automatically when every field of a type implements them. Rc is neither, so trying to use it across threads is a compile error.
Can Rust prevent deadlocks?
No. Safe Rust prevents data races, meaning unsynchronized access to the same memory from two threads where at least one writes. Two threads can still deadlock by locking two mutexes in opposite order, and logic-level race conditions are still possible.
