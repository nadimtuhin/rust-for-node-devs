Appendix 03 • Package Management

Cargo vs npm / pnpm

Additive feature flags, duplicate dependency handling without node_modules, workspace inheritance, pre-1.0 SemVer rules, and release profiles.

1. Rosetta Stone: Core CLI Workflow

Node.js / npm Rust / Cargo What it does
npm init -y cargo init / cargo new <name> Initialize new project
npm install <pkg> cargo add <crate> Add dependency to Cargo.toml
npx tsc --noEmit cargo check Fast type & borrow check without codegen
npm run build cargo build --release Compile optimized machine code
npm test cargo test Run unit & integration tests
npx eslint . cargo clippy Run strict static linter

2. How Cargo Solves the node_modules Problem

In Node.js, duplicate packages often lead to massive nested node_modules and runtime collisions (prototype pollution). Cargo compiles external crates once into target cache. If two dependencies require different major versions (e.g. serde 1.0 and serde 0.9), Cargo mangles the symbols and compiles both side-by-side with zero collisions.

3. Additive Feature Flags & Opt-Out (default-features = false)

In Rust, crate capabilities are gated behind compile-time feature flags. Features are strictly additive: if dependency A enables features = ["derive"] and dependency B does not, Cargo builds the superset union. To minimize binary bloat or replace default libraries (e.g. replacing OpenSSL with pure-Rust rustls), explicitly declare default-features = false:

[dependencies]
# Opt out of heavy default features (e.g. native-tls):
reqwest = { version = "0.12", default-features = false, features = ["rustls-tls", "json"] }
serde = { version = "1.0", default-features = false, features = ["alloc"] }

4. Cargo Workspaces & Dependency Inheritance

Similar to pnpm workspaces or Turborepo, Cargo workspaces allow managing multiple crates with unified lockfiles and shared dependencies via workspace = true:

# Root Cargo.toml
[workspace]
members = ["crates/api", "crates/auth", "crates/db"]

[workspace.dependencies]
tokio = { version = "1.43", features = ["full"] }
serde = { version = "1.0", features = ["derive"] }
tracing = "0.1"

# crates/api/Cargo.toml
[dependencies]
tokio = { workspace = true }
serde = { workspace = true }

5. SemVer Quirks: Pre-1.0 Versions in Cargo vs npm

A major footgun for Node.js engineers is how Cargo handles 0.x versions:

Declared Version Cargo Permitted Range Breaking Change Point
"1.2.3" (or "^1.2.3") >= 1.2.3, < 2.0.0 Bump to 2.0.0
"0.2.3" >= 0.2.3, < 0.3.0 Minor bumps are BREAKING in 0.x!
"0.0.3" == 0.0.3 Patch bumps are BREAKING in 0.0.x!

6. Production Build Profiles & LTO Optimization

In Node.js, minification with esbuild/terser trims bundle size. In Rust, LLVM optimization flags in Cargo.toml strip unused code, inline across crate boundaries, and reduce container binary size by up to 80%:

[profile.release]
opt-level = 3        # Maximum optimizations
lto = "thin"         # Link-Time Optimization across crate boundaries (or "fat")
codegen-units = 1    # Slower compile, maximum binary optimization and inlining
panic = "abort"      # Strip unwinding landing pads (shrinks binary, instant exit)
strip = true         # Automatically strip debug symbols (saves 60-80% binary size)
