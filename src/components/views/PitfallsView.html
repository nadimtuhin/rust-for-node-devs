Appendix 11 • Footguns

Top 8 Rust Footguns for Node Developers

Common misconceptions and pitfalls when transitioning from dynamic JavaScript to systems Rust.

Footgun 1: Calling .clone() to appease the compiler

Calling .clone() duplicates heap memory. If you clone a large buffer on every HTTP request, your service will suffer worse latency than Node.js. Use borrowed references (&T) instead.

Footgun 2: Blocking the Tokio worker thread pool

Calling synchronous file I/O or std::thread::sleep inside an async function blocks the OS worker thread assigned to Tokio, starving hundreds of concurrent requests. Use tokio::time::sleep or tokio::task::spawn_blocking.

Footgun 3: Unbuffered File and Socket I/O

In Node.js, stream buffers are automatic. In Rust, calling file.read() or socket.write() performs a direct kernel syscall per operation. Always wrap with BufReader and BufWriter.

Footgun 4: Production .unwrap() & .expect() Panics

Calling .unwrap() on None or Err causes a thread panic. In Tokio worker tasks, an unhandled panic aborts the task. Use ? error propagation with anyhow or thiserror.

Footgun 5: Cancellation Hazards in tokio::select!

When a branch completes in tokio::select!, other pending futures are immediately dropped. If a future is mid-stream on an AsyncRead, partial bytes are lost unless the future is cancellation-safe.

Footgun 6: Holding std::sync::MutexGuard Across .await

std::sync::MutexGuard does not implement Send, triggering compile-time errors in tokio::spawn. Scope your locks in a block { let val = *lock; } so the guard drops before any .await.

Footgun 7: Memory Leaks via Reference Cycles

Rust has no cycle-detecting garbage collector. Two structs holding Rc or Arc pointers to each other will never reach a reference count of 0, leaking memory forever. Break cycles with Weak<T>.

Footgun 8: Silent Integer Overflow in --release Mode

In debug mode, integer overflow panics. In --release mode, Rust wraps arithmetic using two's complement for speed. For mission-critical calculations, use checked_add() or saturating_add().
