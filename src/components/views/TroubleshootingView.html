Appendix 09 • Diagnostics

Diagnostics, Flamegraphs & Profiling

Exact compilation flags, profiler configurations, and step-by-step diagnostic workflows for zero-overhead systems investigation.

1. CPU Flamegraph Profiling (cargo-flamegraph)

Generates interactive SVG call graphs. Requires release optimizations combined with debug symbols.

Cargo.toml configuration:

[profile.release]
debug = true       # Retain DWARF symbols for function names
strip = false      # Do not strip symbol tables

Execution commands:

# Installation
cargo install flamegraph

# macOS (uses DTrace under the hood; requires root privilege):
sudo cargo flamegraph --bin my-service

# Linux (uses perf; ensure perf events are unlocked):
sudo sysctl -w kernel.perf_event_paranoid=-1
cargo flamegraph --bin my-service

2. Undefined Behavior Detection (cargo miri)

Miri interprets Rust Mid-level Intermediate Representation (MIR) to catch pointer provenance violations, stacked borrow defects, memory leaks, and unaligned reads at runtime.

# Install nightly toolchain & Miri component
rustup toolchain install nightly --component miri
rustup override set nightly

# Run tests under Miri interpreter
cargo miri test

# Strictest borrow checking with Tree Borrows & pointer provenance validation:
MIRIFLAGS="-Zmiri-tree-borrows -Zmiri-strict-provenance -Zmiri-track-raw-pointers" cargo miri test

3. Real-Time Async Task Tracing (tokio-console)

Inspect task scheduling starvation, blocked async executors, and full channel backpressures live.

// 1. Cargo.toml dependency:
// console-subscriber = "0.4"

// 2. In src/main.rs before initializing Tokio runtime:
#[tokio::main]
async fn main() {
    console_subscriber::init();
    // ... rest of service
}
# 3. Compile service with Tokio unstable flags enabled:
RUSTFLAGS="--cfg tokio_unstable" cargo run

# 4. In a separate terminal, launch the console TUI:
cargo install tokio-console
tokio-console http://127.0.0.1:6669

4. Memory Allocation & Heap Profiling (DHAT & Valgrind)

Track heap churn, short-lived allocations, and memory leaks down to the byte without runtime penalties.

// Using DHAT (Dynamic Heap Analysis Tool) inside Rust:
#[cfg(feature = "dhat-heap")]
#[global_allocator]
static ALLOC: dhat::Alloc = dhat::Alloc;

fn main() {
    #[cfg(feature = "dhat-heap")]
    let _profiler = dhat::Profiler::new_heap();
    // application logic...
    // Writes `dhat-heap.json` upon graceful exit
}
# Linux Valgrind Massif (Heap Profiling):
valgrind --tool=massif --pages-as-heap=yes target/release/my-service
ms_print massif.out.<pid>
