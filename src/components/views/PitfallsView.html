Appendix 11 • Footguns

Top 8 Rust Footguns for Node Developers

Common misconceptions and pitfalls when transitioning from dynamic JavaScript to systems Rust.

Footgun 1: Calling .clone() to appease the compiler

Calling .clone() duplicates heap memory allocations. If you clone a 50MB buffer on every incoming HTTP request, your performance will be worse than Node.js! Take borrowed references (&T) instead.

Footgun 2: Blocking the Tokio thread pool

Node.js developers used to single-threaded async sometimes use synchronous file reads or std::thread::sleep inside async blocks. In Tokio, this starves worker threads!
